Tender Main Layouts #1808 · Main is 348 px wide, 420 px tall before it scrolls

LAYOUT
Die Frage
Main hat drei Türen zur Sync-Seite — die drückbare Last sync-Zeile, den Sync Library-Knopf und den Menüeintrag — und der Knopf berechnet beim Drücken eine Vorschau, die man vielleicht gar nicht wollte. Was hier zur Wahl steht, ist nicht die Tür zu Sync allein, sondern die Regel für alle Seiten.
Die Falz
Der Panel ist 454 px hoch, davon gehen 34 px an Deckys Titelzeile: 420 px sind sichtbar. Die rote Linie in den Zeichnungen ist diese Grenze — was darunter liegt, erreicht man nur, indem man den Fokus Zeile für Zeile hinunterschiebt. Es gibt keinen zweiten Weg: das QAM scrollt nur über den Fokus.
Jeder Halt zählt
Jede fokussierbare Zeile ist ein Stick-Druck. Connection, Library und Steam memory sind heute Haltestellen, an denen nichts passiert — man läuft durch sie hindurch, um ans Menü zu kommen.
Unverändert in allen drei
Kein Knopf auf Main berechnet noch etwas. Hinweise behalten ihre eigenen Aktionsknöpfe. Läuft ein Sync, steht der Fortschrittsblock mit Cancel auf Main — das ist Anzeige, keine Tür, und bleibt einen Druck entfernt.

A · Status ist die Karte

Jede Statuszeile führt zu der Seite, der ihre Tatsache gehört. Der eigene Sync-Knopf entfällt, das Menü behält nur, was keine Zeile beschreibt. Aus drei toten Haltestellen werden drei Türen — und die Navigation rückt an den oberen Rand, wo sie billig zu erreichen ist.

Entscheidung B, mit dem konditionalen Platz — hier als B+ gezeichnet. Das Menü bleibt vollständig und ist die einzige Navigationsfläche; die Statuszeilen tun nichts. Was B allein fehlte, war ein Ort für die Dinge, die sich von selbst melden müssen — ein laufender Lauf und eine wartende Vorschau. Beide bekommen denselben konditionalen Platz unter dem Status, der nur dann existiert und als einziger Teil des Status drückbar ist. Damit hat Main nie mehr als eine Tür zur Sync-Seite, die aber immer da, wo man gerade hinschaut. Steam memory zieht auf die Sync-Seite um. Offen bleibt nur, ob Cancel Sync auf Main stehen bleibt — die beiden mittleren Zeichnungen stellen genau das gegenüber.

Offene Unterfrage, unabhängig von der Wahl

  • Steam memory ist eine Diagnosezeile. Sie hat auf der Sync-Seite ihre eigene Karte und meldet sich von selbst als Hinweis, wenn es eng wird. Fällt sie auf Main weg, bleiben in A genau drei Zeilen — eine pro Seite, die einen Zustand hat.
  • Fortsetzen kostet in allen drei Entwürfen zwei Drücke statt einem: Tür, dann der Startknopf auf der Seite, auf dem der Fokus schon liegt. Soll Main für diesen einen Fall doch einen eigenen Knopf behalten?
